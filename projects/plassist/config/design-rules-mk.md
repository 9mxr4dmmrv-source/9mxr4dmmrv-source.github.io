# マーケティング設計ルール（メインセッション用・STP）

メインでマーケ施策を設計・作成するときにこのファイルに従う。
※ このファイルは mk-critic には渡さない。狙いを見せると評価が寄るため。

## 考え方
STP で設計する。商品 = Plassist、顧客 = 時間管理に悩むターゲット、競合 = 他の時間管理アプリ。
顧客が価値を置く点に対し、競合がやっていない切り口で差別化し、
どのチャネル（ASO / 発信 / LP）でどう position するかを決めてから作る。
（ES で自分に適用した STP を、今度はプロダクトに適用する）

## 入力（所与）
- findings.md … mk-analyst がまとめた指標の現状（獲得/維持/訴求の課題）。
- marketing/data … 実数字の唯一のソース。ここにない数字は使わない。
- 目的 … あなたが述べる、または idea.md で整理した一枚。

## フェーズA: 現状把握
- findings を所与に、いま弱い所／伸びしろを「獲得・維持・訴求」のどこか1〜2点に絞る。

## フェーズB: 施策設計
- 打つ施策（ASO文言/スクショ構成、発信、LP改善）を優先度つきで並べる。
- 各施策が findings のどの課題への「答え」かを明示する。
- ここで一度あなたの確認を待つ。合意の前に作り始めない。

## フェーズC: 作成
- 合意後、メインで成果物を作る。事実・数字は marketing/data から正確に引用。創作しない。
- 仕上げに mk-critic で独立評価。指摘を逐条で直さず、本質と些末を仕分けて根本を直す。

## やらないこと
- 作成段階で自画自賛の評価をしない（mk-critic が独立して行う）。
